# Этап 1: фундамент для многих пользователей

## Контекст и цель

gym95 переходит от личного бота к дневнику для владельца и круга друзей (концепция: [2026-10-20-body-diary-concept.md](2026-10-20-body-diary-concept.md)). Сейчас бот сделан под одного человека: часовой пояс `Europe/Moscow` зашит в коде (`src/cron/reminders.ts`, тексты `/settings`), нет профиля, норм, знакомства и ограничения доступа.

**Цель этапа:** заложить основу, на которую потом без переделок встанут модули (вес, активность, вода, еда, сон):
профиль, знакомство с ботом, вход по приглашению, часовой пояс каждого пользователя, реестр модулей, экран `/today`, `/settings` по разделам, запись тренировок задним числом.

**Не входит:** функциональность модулей веса, активности, воды, еды и сна; шаблоны тренировок; вечерний итог дня; админ-функции, кроме `/invite`; изменения легаси-пути для Vercel (`webapp/api/*`).

Тон бота остаётся прежним: обращение на «ты».

## 1. Данные

Миграция дописывается в конец `migrations/schema.sql`. Она только добавляет объекты, поэтому старый код работает и на новой схеме.

```sql
create table if not exists profiles (
  user_id      bigint primary key,
  goal         text not null check (goal in ('lose', 'gain', 'regular')),
  sex          text not null check (sex in ('male', 'female')),
  birth_year   int  not null check (birth_year between 1930 and 2020),
  height_cm    int  not null check (height_cm between 120 and 230),
  timezone     text not null default 'Europe/Moscow',
  invited_by   bigint null,
  onboarded_at timestamptz not null default now(),
  created_at   timestamptz not null default now()
);

create table if not exists user_modules (
  user_id  bigint not null,
  module   text   not null check (module in ('weight', 'activity', 'water', 'food', 'sleep')),
  enabled  boolean not null default false,
  settings jsonb  not null default '{}'::jsonb,
  primary key (user_id, module)
);

create table if not exists invites (
  code       text primary key,
  created_by bigint not null,
  uses_left  int not null default 1 check (uses_left >= 0),
  created_at timestamptz not null default now()
);

create table if not exists body_weights (
  id          uuid primary key default gen_random_uuid(),
  user_id     bigint not null,
  weight_kg   numeric(5,1) not null check (weight_kg between 35 and 300),
  measured_at timestamptz not null default now()
);
create index if not exists idx_body_weights_user_time on body_weights (user_id, measured_at desc);
```

- Возраст хранится как `birth_year`: «возраст» в профиле вычисляется и не устаревает.
- Вес из знакомства записывается первой строкой `body_weights`. Остальной модуль веса — этап 2.
- `user_settings` не меняется. Время напоминания (`reminder_time`) теперь трактуется в часовом поясе из `profiles.timezone`.
- Норма воды хранится в `user_modules.settings` модуля `water` (`{"dailyMl": 2500}`), хотя сам модуль появится только на этапе 4. Так при его выходе норма уже будет посчитана.

Слой доступа: `src/db/profiles.ts` (`getProfile`, `createProfileWithInvite`, `updateProfile`), `src/db/modules.ts` (`getModules`, `setModule`), `src/db/invites.ts` (`createInvite`).

**Приглашение списывается атомарно.** В Postgres создаётся функция `redeem_invite_and_create_profile(...)`, которая в одной транзакции уменьшает `uses_left` (`update ... where code = $1 and uses_left > 0 returning`), создаёт профиль и вставляет первую запись веса. Вызывается через `supabase.rpc`. Если строк не обновилось, функция возвращает ошибку `invite_invalid`.

## 2. Доступ

- Новая **обязательная** переменная окружения `OWNER_ID` (Telegram id владельца) читается в `src/config.ts` так же, как `BOT_TOKEN`: без неё процесс не стартует и пишет понятную ошибку. Мягкий режим не делаем: без `OWNER_ID` знакомство владельца потребовало бы приглашения, которое некому создать. Поэтому в выкатке переменная добавляется до пуша.
- **Middleware** `src/handlers/access.ts` регистрируется в `botInstance.ts` **первым**, до `registerStart`. Решение принимает чистая функция `decideAccess({ isOwner, hasProfile, onboardingInProgress, startPayload })`:
  - `allow` — есть профиль;
  - `onboard` — профиля нет, но это владелец, или идёт знакомство, или пришёл `/start inv_<код>`. Действительность кода проверяется при завершении знакомства, а не здесь;
  - `deny` — всё остальное. Ответ: «Доступ по приглашению. Попроси ссылку у того, кто рассказал тебе о боте.»
- Профили кэшируются в памяти процесса на 5 минут. При создании или изменении профиля кэш этого пользователя сбрасывается.
- **Mini App:** API `/api/*` в `src/webapp/server.ts` после проверки `initData` проверяет наличие профиля. Если профиля нет, возвращается 403.
- **`/invite`** (только для владельца, другим не отвечает): создаёт код из 8 символов `[a-z0-9]` с `uses_left = 1` и присылает ссылку `https://t.me/<username бота>?start=inv_<код>`, плюс подсказку «Ссылка одноразовая».

## 3. Знакомство

Новый FSM `src/handlers/onboarding/` (`state.ts`, `index.ts`, `parse.ts`). Состояние в памяти: `Map<userId, OnboardingSession>`, где `{ step, inviteCode?, goal?, heightCm?, weightKg?, age?, sex?, timezone? }`. Поток регистрируется в `activeFlow.ts` как `'onboarding'`.

Шаги:

1. **Цель** — кнопки «📉 Похудеть», «💪 Набрать мышцы», «🔁 Регулярность и форма» (`ob:goal:<lose|gain|regular>`).
2. **Рост, вес, возраст** — текстом «182 95 34». Разбирает `parseBodyLine(text)`: три числа через пробелы или запятые, вес с дробной частью через точку или запятую, диапазоны: рост 120–230, вес 35–300, возраст 12–90. При ошибке бот присылает пример формата и остаётся на шаге.
3. **Пол** — кнопки (`ob:sex:<male|female>`).
4. **Часовой пояс** — кнопки (`ob:tz:<IANA>`), МСК первой:
   МСК−1 `Europe/Kaliningrad`, МСК `Europe/Moscow`, МСК+1 `Europe/Samara`, МСК+2 `Asia/Yekaterinburg`, МСК+3 `Asia/Omsk`, МСК+4 `Asia/Krasnoyarsk`, МСК+5 `Asia/Irkutsk`, МСК+6 `Asia/Yakutsk`, МСК+7 `Asia/Vladivostok`, МСК+8 `Asia/Magadan`, МСК+9 `Asia/Kamchatka`.
5. **Модули** — галочки по доступным модулям, предвыбранные по цели. В этапе 1 доступных модулей нет, поэтому шаг пропускается.
6. **Завершение:** вызов `redeem_invite_and_create_profile`. Владелец проходит без кода, остальные — с кодом из `/start`. Затем строки `user_modules` по стартовому набору цели и итоговое сообщение с нормами и кнопкой «Открыть «Сегодня»».

Поведение:
- `/start` во время знакомства продолжает с текущего шага. `/start inv_<код>` при существующем профиле просто открывает `/today`, приглашение не тратится.
- Если состояние потерялось (перезапуск процесса), при следующем сообщении знакомство начинается заново. Код приглашения берётся из нового `/start`. Если кода нет, бот просит открыть ссылку ещё раз.
- Если код оказался недействительным на шаге 6: «Ссылка недействительна или уже использована. Попроси новую.» Сессия удаляется.
- Для владельца, у которого уже есть тренировки, старые данные остаются как есть: `user_id` тот же.

## 4. Реестр модулей и нормы

`src/modules/registry.ts`:

```ts
type ModuleId = 'weight' | 'activity' | 'water' | 'food' | 'sleep';
interface ModuleDef {
  id: ModuleId;
  title: string;                 // «⚖️ Вес»
  available: boolean;            // в этапе 1 у всех false
  defaults: Record<Goal, { enabled: boolean; settings: object }>;
  todaySection?: (userId: number, ctx: TodayContext) => Promise<string | null>;
}
```

- Стартовые наборы по цели — из таблицы в концепции. В этапе 1 записываются строки `user_modules` с `enabled` по цели. Пока `available = false`, модули нигде не показываются.
- **Анонс нового модуля** (используется с этапа 2): когда модуль становится `available`, всем профилям, у которых модуль ещё не анонсирован, бот один раз пишет «Новое: <title>. Включить?». Анонс отмечается в `user_modules.settings.announced = true`. Механизм закладывается в этапе 1, но анонсировать пока нечего.

`src/utils/norms.ts`:
- `waterNormMl({ heightCm, weightKg })`: идеальный вес = 22 × рост²(м). Если реальный больше идеального, расчётный = идеальный + 0,4 × (реальный − идеальный), иначе расчётный = реальный. Норма = 30 мл × расчётный, ограничение 1500–3000 мл, округление до 250 мл.
  Проверочные точки: 182 см / 95 кг → 2500 мл; 182 см / 130 кг → 2750 мл; 160 см / 50 кг → 1500 мл.

## 5. Часовые пояса

`src/utils/time.ts` (без сторонних библиотек, на `Intl.DateTimeFormat`):
- `localNow(tz)` → `{ dateStr: 'YYYY-MM-DD', hhmm: 'HH:MM', weekday }`;
- `localMidnightUtc(dateStr, tz)` и `localNoonUtc(dateStr, tz)` → `Date` в UTC;
- `localWeekStart(tz)` → понедельник текущей местной недели, `YYYY-MM-DD`.

Где меняется:
- **`src/cron/reminders.ts`**: убрать `MOSCOW_TZ`. `getUsersNeedingReminder` заменяется на выборку всех `reminders_enabled = true` вместе с `profiles.timezone`. Для каждого пользователя `localNow(tz).hhmm` сравнивается с `reminder_time`. Защита `last_reminder_sent_date` работает по местной дате. Если профиля нет, используется `Europe/Moscow`.
- **`src/handlers/settings.ts`**: убрать надписи «(Europe/Moscow)», показывать пояс пользователя.
- **`src/webapp/queries.ts`**: недельные границы (`lastMondays`, сводка, недельная цель) считаются от `localWeekStart(tz)` профиля.

## 6. `/today`

`src/handlers/today.ts`: команда `/today`, кнопка в меню команд (`setMyCommands`), и тот же экран после завершения знакомства.

Собирается из блоков: сначала встроенный блок «Тренировки», затем `todaySection` каждого доступного и включённого модуля (в этапе 1 их нет).

Блок «Тренировки»:
```
Сегодня, вторник 20 октября

🏋️ Сегодня тренировки не было
   Последняя: вчера · силовая
   Неделя: 2 / 3
```
Если сегодня тренировка уже была: «🏋️ Сегодня: силовая ✓». Клавиатура: «🏋️ Записать тренировку» (→ тот же вход, что `/new_workout`), «📊 Mini App» (если задан URL Mini App).

`/start` для пользователя с профилем показывает краткую справку по командам и затем `/today`.

## 7. Записи задним числом

В `/new_workout`, на экране выбора типа тренировки (`typeStep.ts`), появляется кнопка «📅 Другая дата» (`w:date`). Дальше кнопки «Вчера», «Позавчера» и подсказка «или напиши дату дд.мм». Выбранная дата хранится в черновике (`DraftWorkout.date?: string`, `YYYY-MM-DD`) и показывается в заголовке черновика: «📅 18.10».

- `parseDayMonth(text, todayLocal)`: `дд.мм` или `дд.мм.гггг`. Без года подставляется ближайший прошлый год, в котором эта дата не в будущем. Будущие даты и даты старше 365 дней отклоняются, несуществующие (31.04, 29.02 не в високосный год) тоже.
- При сохранении (`saveDraftWorkout`): если `date` задана, `workouts.date = localNoonUtc(date, tz)`, иначе текущее время, как сейчас.
- Повтор тренировки получает такую же кнопку, когда его реализация будет закончена. Если на момент реализации этапа 1 повтор уже влит, кнопка добавляется в его экран превью.

## 8. `/settings`

Главное меню разделов (`s:menu`):
- **👤 Профиль** (`s:profile`): цель, рост, вес, возраст, пол, часовой пояс. Каждое поле правится отдельно, ввод тот же, что в знакомстве (переиспользуются `parseBodyLine` и клавиатура поясов). Новый вес пишется новой строкой `body_weights`. При смене цели или роста и веса бот предлагает «Пересчитать норму воды?» — пересчитывает только по кнопке «Да».
- **🏋️ Тренировки**: текущие настройки (напоминание вкл/выкл, время, недельная цель) без изменений логики.
- **🧩 Модули**: скрыт, пока нет доступных модулей.

Ввод текста в профиле использует существующий механизм `settingsState.ts` (новые виды ожидаемого ввода), поэтому `activeFlow` не меняется.

## 9. Ошибки

- **База недоступна** (ошибка сети или 5xx от Supabase в любом обработчике): общий обработчик в `bot.catch` отвечает «Сервис временно недоступен, попробуй через пару минут» и пишет ошибку в лог. Сейчас пользователь в такой ситуации не получает ответа вовсе.
- **Неверный ввод** в знакомстве и профиле: пример формата, шаг не меняется.
- **Двойное нажатие** на кнопку завершённого шага знакомства: `answerCbQuery` без действия.
- **Недействительное приглашение**: см. раздел 3.

## 10. Тесты

В проекте сейчас нет тестов. Добавляется `node:test` через уже установленный `tsx`, без новых зависимостей:
- `package.json`: `"test": "tsx --test src/**/*.test.ts"`;
- тесты лежат рядом с кодом (`*.test.ts`); корневой `tsconfig` исключает их из сборки.

Покрываем чистые функции:
- `norms.test.ts`: три проверочные точки и обе границы (1500 и 3000 мл);
- `time.test.ts`: `localNow` для `Europe/Moscow` и `Asia/Vladivostok` около полуночи UTC; `localNoonUtc` даёт ту же местную дату; `localWeekStart` в понедельник и воскресенье;
- `parse.test.ts`: `parseBodyLine` (запятые, дробный вес, выход за диапазон, лишние и недостающие числа); `parseDayMonth` (будущее, старше года, 29.02, переход через Новый год);
- `access.test.ts`: все ветки `decideAccess`.

Ручной чек-лист в Telegram (после выкатки):
1. Владелец: первое сообщение → знакомство → `/today` показывает прошлые тренировки.
2. `/invite` → ссылка открыта со второго аккаунта → знакомство проходит, повторное открытие той же ссылки третьим аккаунтом → «недействительна».
3. Аккаунт без приглашения → «Доступ по приглашению», Mini App → 403.
4. Пояс `Asia/Vladivostok` у второго аккаунта, напоминание на ближайшую минуту по владивостокскому времени → приходит.
5. Тренировка «Позавчера» → в `/history` и Mini App стоит правильная дата.
6. `/settings` → Профиль → смена веса → предложение пересчитать норму.

## 11. Выкатка

1. Применить миграцию к базе **до** пуша: `supabase db query --linked -f migrations/schema.sql`. Схема только расширяется, текущий прод продолжает работать.
2. Добавить `OWNER_ID` в Environment на Render.
3. Пуш в `master` → автодеплой.
4. Владелец проходит знакомство, затем `/invite`.

Перед этапом 1 закрываются хвосты этапа 0 (отдельные задачи, не часть этого спека): GitHub Actions-пинг Supabase и разбор логов Render за время простоя.

## Известные расхождения

- Легаси-путь для Vercel (`webapp/api/*`) не получает ни проверки профиля, ни местных недель. Он не используется в проде. Перед любым переездом на Vercel его нужно догнать.
