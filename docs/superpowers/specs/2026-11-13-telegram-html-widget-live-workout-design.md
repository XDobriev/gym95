# Дизайн: Интерактивный Live Workout через Telegram HTML Widgets (Bot API 10.4)

**Дата:** 2026-11-13  
**Проект:** gym95  
**Статус:** Draft на согласовании  

---

## 1. Контекст и цель

В Telegram Bot API 10.4 появилась поддержка **Interactive HTML Widgets** (`sendWidget`, `editMessageWidgetData`, `answerWidgetQuery`), которые рендерятся прямо внутри пузыря сообщения в нативной песочнице QuickJS на клиенте.

### Проблема:
В спортзале атлету неудобно:
1. Переписываться с ботом десятками сообщений на каждый подход (спам в чате, задержка ответа сети, прыгающая клавиатура).
2. Каждый раз открывать Telegram Mini App во весь экран ради одного подхода (лишние тапы, перекрытие чата).

### Решение:
Внедрить **Live Workout HTML Widget** прямо в ленту переписки бота:
* Одно интерактивное сообщение на упражнение.
* Мгновенные степперы веса (`±2.5 кг`) и повторов (`±1`) без задержки сети.
* Живой таймер отдыха прямо в виджете (обратный отсчёт, кнопка `+30 сек`).
* Автоматическая фиксация сетов в базе данных Supabase (`workout_sets`).
* Полный фирменный стиль gym95: шрифт Anton для весов, токсичный неоновый лайм (`#c9ff2e`), тёмный спортзальный фон.

## 2. Архитектура и транспорт Telegram Bot API 10.4

### 2.1 Низкоуровневый адаптер (`src/utils/telegramWidgets.ts`)
Поскольку в библиотеке `telegraf` (`^4.16.3`) методы для Bot API 10.4 ещё не объявлены, создаётся строгий типизированный модуль:

```typescript
export interface WidgetSendOptions {
  chat_id: number | string;
  html: string; // до 32 КБ (исходный код HTML + inline CSS + inline JS)
  chat_data?: string; // начальное JSON-состояние (до 1024 байт)
  reply_to_message_id?: number;
}

export interface WidgetDataEditOptions {
  chat_id: number | string;
  message_id: number;
  chat_data: string; // обновлённый JSON-стейт
}

export interface WidgetQueryAnswerOptions {
  widget_query_id: string;
  text?: string;
  show_alert?: boolean;
}
```

Все методы вызывают нативный транспорт `ctx.telegram.callApi(...)`.

### 2.2 Двусторонний обмен событиями (Event Flow)
1. **Бот → Виджет:** `sendWidget(chatId, HTML_BUNDLE, { chat_data: JSON.stringify(initialState) })`.
2. **Локальный UI:** Быстрые действия (изменение веса `+2.5`, повторов `+1`) меняют локальный DOM мгновенно в QuickJS без сетевых задержек.
3. **Виджет → Бот:** По кнопке «Завершить подход» скрипт виджета вызывает `TelegramWidget.request({ action: 'finish_set', weight, reps, setIndex })`.
4. **Бот → База данных:** Обработчик события `widget_query` валидирует данные, сохраняет сет в Supabase, запускает таймер отдыха.
5. **Бот → Виджет (реактивное обновление):** Бот вызывает `editMessageWidgetData(chatId, messageId, nextState)`.
6. **Виджет ловит событие:** `TelegramWidget.onEvent('chatDataChanged', (data) => render(data))` и переключает режим карточки на «Отдых» с тикающим таймером.

## 3. Спецификация состояния данных (`chat_data`)

Размер `chat_data` строго ограничен Telegram (до 1024 байт). Состояние максимально компактно:

```json
{
  "wid": "w_9872",
  "ex": "Жим лёжа на скамье",
  "sn": 3,
  "st": 4,
  "w": 92.5,
  "r": 8,
  "pw": 90.0,
  "pr": 8,
  "m": "active",
  "rta": 1731526400000,
  "rd": 90
}
```

* `wid`: ID тренировки (`workout_id`).
* `ex`: Название текущего упражнения.
* `sn`: Номер текущего сета (`set_number`).
* `st`: Целевое число сетов (`sets_total`).
* `w`: Текущий рабочий вес (кг).
* `r`: Текущие повторения.
* `pw`, `pr`: Прошлый результат (ghost values) для ориентации атлета.
* `m`: Режим (`"active"` — выполнение подхода, `"resting"` — отдых между сетами, `"done"` — упражнение завершено).
* `rta`: Время окончания отдыха (`rest_ends_at`, timestamp в мс).
* `rd`: Базовая длительность отдыха в секундах (по умолчанию 90с).

## 4. UI/UX и дизайн виджета (Design System: gym95)

Виджет строго соблюдает правила `DESIGN.md`:

### Визуальные константы:
* **Display Font:** `Anton, sans-serif` для чисел веса, повторов и таймера.
* **Text / Labels:** `Barlow` (body) и `Barlow Semi Condensed` (лейблы, бейджи, кнопки).
* **Цвета:**
  * Акцент: Токсичный лайм `#c9ff2e` (свечение `--lime-glow: rgba(201, 255, 46, 0.35)`).
  * Фон виджета: `#131922` с тонкой границей `#232c3a`.
  * Текст: Основной `#f0f2f5`, вторичный `#8a94a6`.
  * Статус отдыха / подтверждения: Тил `#00e0a4`.

### Режимы интерфейса:
1. **Режим выполнения (`active`):**
   * Заголовок: название упражнения и бейдж сета (`СЕТ #3`).
   * Сетка контролов: степпер веса `[-2.5] 92.5 кг [+2.5]` и степпер повторов `[-1] 8 повт [+1]`.
   * Блок быстрого старта отдыха: отображение запланированного времени отдыха.
   * Главная кнопка: `[✓ ЗАВЕРШИТЬ ПОДХОД]` (акцентный лайм, высота 48px для лёгкого тапа пальцем).
2. **Режим отдыха (`resting`):**
   * Таймер обратного отсчёта (`01:28` крупным шрифтом Anton).
   * Кнопка `[+30 сек]` для быстрой прибавки времени.
   * Кнопка `[Пропустить / Начать подход]`.
3. **Режим завершения (`done`):**
   * Итоговая сводка выполненных сетов: `3 сета • Тоннаж 2 220 кг`.
   * Кнопка перехода к следующему упражнению или завершения тренировки.

## 5. Интеграция с существующей кодовой базой

1. **База данных Supabase:**
   * Используются существующие функции из `src/db/workouts.ts`: `addExercise(workoutId, exerciseName)` и `saveExerciseSets(exerciseId, sets)`.
2. **Обработчик бота:**
   * В `src/handlers/workout/` добавляется модуль `widgetStep.ts`, перехватывающий шаги тренировки при включённой поддержке виджетов.
   * Добавляется обработчик `bot.on('widget_query', handleWidgetQuery)`.
3. **Обратная совместимость (Fallback):**
   * Если Telegram-клиент пользователя не поддерживает `sendWidget`, метод возвращает ошибку API (`METHOD_NOT_AVAILABLE` или клиентский fallback).
   * В этом случае бот автоматически переключается на классический диалог с `InlineKeyboardMarkup` (существующий `setsInputStep.ts`), гарантируя 100% работоспособность для всех пользователей.

## 6. План тестирования и верификации (Playwright & Unit Tests)

1. **Unit-тесты (Node.js test runner):**
   * Сериализация и десериализация `chat_data` (проверка укладывания в лимит 1024 байт).
   * Валидация вычислений веса/повторов при шагах `+2.5 / -2.5`.
   * Обработка событий `widget_query` и корректность вызовов `saveExerciseSets`.

2. **E2E и визуальные тесты (Playwright):**
   * Загрузка HTML-шаблона виджета в изолированном headless/UI браузере на мобильных разрешениях (360x640, 390x844 iPhone, 412x915 Pixel).
   * Тестирование кликов по степперам: проверка мгновенного изменения DOM-дерева без задержек.
   * Проверка работы таймера отдыха: корректность обратного отсчёта, добавление `+30 сек`.
   * Проверка контрастности (WCAG AA): соответствие текста весов и кнопок стандартам доступности.
   * Захват скриншотов эталонных состояний (`active`, `resting`, `done`) для дизайн-ревью.
