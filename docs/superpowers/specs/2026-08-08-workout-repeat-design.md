# Повтор тренировки

## Контекст и цель

`/new_workout` требует заново вводить каждое упражнение и каждый подход даже тогда, когда тренировка почти дословно повторяет одну из прошлых (типичный случай для силовых — один и тот же сплит с плюс-минус теми же весами). Это самое частое и самое муторное по числу нажатий действие в боте. Фича «Повтор тренировки» была отдельно запланирована ещё в спеке [2026-07-14-workout-delete-edit-design.md](2026-07-14-workout-delete-edit-design.md) («Вне области этого спека») как одна из следующих.

**Область этого спека:** повтор конкретной прошлой тренировки — без именованных шаблонов, только силовой тип. Пользователь выбирает исходную тренировку (только что сохранённую или из истории), бот собирает из неё черновик с уже подставленными упражнениями и подходами, пользователь принимает как есть или точечно правит, затем сохраняет как новую запись с сегодняшней датой.

**Не входит в этот спек:** кардио/бассейн/смешанные тренировки (нет кнопки «Повторить» для них в v1), именованные шаблоны, правка разминки прямо на экране предпросмотра, изменения в Mini App (там вообще нет экрана создания тренировки — добавлять его ради этой фичи было бы отдельной большой задачей).

## Точка входа

Две кнопки, обе видны только когда `workout.type === 'strength'`:

1. **После `/done`** — в сообщении с итогом сохранённой тренировки появляется кнопка «🔁 Повторить это» рядом с текстом (сейчас там вообще нет клавиатуры).
2. **В `/history`** — на карточке тренировки, рядом с уже существующими «✏️ Изменить» / «🗑 Удалить».

Обе ведут на один и тот же callback `w:repeat:<workoutId>` — единственное различие между ними в том, что после `/done` тренировка ещё «свежая» (её id только что вернула `saveDraftWorkout`), а в истории берётся id уже сохранённой записи. Логика обработки идентична.

## Поток

1. Тап «🔁 Повторить» → те же проверки конфликта, что и у `/new_workout`: если уже есть незавершённый черновик — предложить «Продолжить/Начать заново» (как сейчас); иначе если активен другой поток (правка тренировки, `/settings`) — блокирующее сообщение через `otherActiveFlow`/`activeFlowBlockedMessage` (переиспользуется как есть, без изменений).
2. Бот загружает исходную тренировку (`getWorkoutOwned` + `getExercisesByWorkoutId`). Если не найдена (удалена) — «Тренировка не найдена — возможно, уже удалена.», черновик не создаётся. Если у неё нет упражнений (не должно случаться для силовой, но на всякий случай) — «В той тренировке не было упражнений — нечего повторять.».
3. Создаётся новый черновик (`startDraft`), в него копируется: `type = 'strength'`, `warmupMinutes` из исходной (как есть, без правки на этом экране), `exercises` — полная копия списка (имя + подходы + порядок). Шаг черновика — новый `reviewing_repeat`.
4. Бот показывает экран-превью:

   ```
   🔁 Повтор тренировки от 05.03.2026

   1. Жим лёжа: 40x12, 40x12, 42.5x10
   2. Тяга блока: 60x10, 60x10

   Прими как есть или поправь упражнение кнопкой,
   затем «✅ Завершить тренировку».
   ```

   Клавиатура: по паре кнопок `✏️ <название>` / `🗑` на каждое упражнение (как в `editMenuKeyboard`), затем `➕ Добавить упражнение`, `✅ Завершить тренировку`, `❌ Отменить`.

5. **`✏️ <название>`** — то же сообщение-приглашение, что при правке сохранённой тренировки: «`<название>`. Сейчас: `40x12, 40x12`. Введи новые подходы взамен, например: `40x12, 40x12`». Следующий текстовый ответ **заменяет** (не дописывает) подходы этого упражнения и возвращает на экран превью.
6. **`🗑`** — убирает упражнение из черновика, пересчитывает `orderIndex` оставшихся, перерисовывает превью. Если это было последнее упражнение — работает как обычно (превью с пустым списком, «Завершить» в этом состоянии не сохранит тренировку, см. `saveDraftWorkout`'а существующую защиту от пустого черновика).
7. **`➕ Добавить упражнение`** — это буквально существующий `handleNextExercise`: выбор упражнения → ввод подходов → пользователь попадает в уже существующий `exercise_saved_menu` (со списком «Ранее в тренировке», куда войдут и предзаполненные упражнения). Дальше — обычный путь: «Ещё подход» / «Следующее упражнение» / «✅ Завершить тренировку». Отдельного возврата на `reviewing_repeat` не требуется — `w:finish` работает независимо от текущего шага.
8. **`✅ Завершить тренировку`** / **`❌ Отменить`** — существующие `handleFinishAction` / `handleCancelWorkoutAction`, без изменений. Новая тренировка сохраняется с датой «сейчас» (`createWorkout` и так по умолчанию берёт `new Date()`, когда `date` не передан).

## Технические детали

- `types/draft.ts`:
  - `WorkoutStep` — новое значение `'reviewing_repeat'`.
  - `DraftWorkout` — новые опциональные поля: `editingExerciseIndex?: number` (какое упражнение в `exercises` сейчас заменяется через `entering_sets`), `repeatSourceDate?: string` (дата исходной тренировки, только для заголовка превью).
- `src/handlers/workout/setsInputStep.ts` → `handleSetsTextEntered`: в начале функции — если `draft.editingExerciseIndex !== undefined`, заменить `exercises[index].sets` на новый результат парсинга, сбросить `editingExerciseIndex`, `setStep('reviewing_repeat')`, отрендерить превью и выйти; иначе — существующий путь без изменений.
- Новый файл `src/handlers/workout/repeatStep.ts`:
  - `buildDraftFromWorkout(userId, chatId, workout, exercises)` — заполняет черновик, как описано в шаге 3.
  - `renderRepeatReview(ctx, draft)` — текст + клавиатура превью.
  - `repeatReviewKeyboard(exerciseNames: string[])` — новая функция в `keyboards.ts`, по образцу `editMenuKeyboard`.
  - `registerWorkoutRepeat(bot)`: `w:repeat:<workoutId>` (шаги 1–4), `w:repeat_edit_ex:<index>` (шаг 5, запускает `entering_sets` с `editingExerciseIndex`), `w:repeat_del_ex:<index>` (шаг 6). Регистрируется в `botInstance.ts` рядом с `registerWorkout`/`registerWorkoutEdit`.
- `src/handlers/workout/index.ts` → `renderCurrentStep` (используется кнопкой «▶️ Продолжить» после случайного ухода из диалога): новый `case 'reviewing_repeat'`, перерисовывающий превью через `renderRepeatReview`.
- `src/handlers/workout/finish.ts` → `FinishResult` (ветка `ok: true`) — добавить `workoutId: string` и `type: WorkoutType`, чтобы вызывающий код знал, показывать ли кнопку «Повторить это».
- `src/handlers/workout/index.ts` → `handleDoneCommand`/`handleFinishAction`: если `result.ok && result.type === 'strength'`, добавить `reply_markup` с кнопкой `w:repeat:<result.workoutId>`.
- `src/handlers/history.ts` → `workoutCardKeyboard(workoutId, offset)`: добавить параметр `type: WorkoutType`, условно добавлять кнопку `w:repeat:<workoutId>` в первый ряд. Оба места вызова (`sendHistoryPage` в `history.ts`, `renderCardById` в `editStep.ts`) уже имеют `workout` в области видимости — прокинуть `workout.type`.
- База данных — без изменений, только переиспользование существующих `getWorkoutOwned`, `getExercisesByWorkoutId`, `createWorkout`, `addExercise`.
- Guard от пересечения с другими FSM (`/settings`, правка тренировки) — переиспользуется существующий `src/handlers/activeFlow.ts` (`otherActiveFlow(userId, 'draft')`), без изменений в нём самом.

## Тестирование

Формального набора тестов в проекте нет — ручной прогон в реальном боте (dogfood), как и для предыдущих фич:
1. Сохранить силовую тренировку с 2–3 упражнениями, тапнуть «🔁 Повторить это» из сообщения `/done` — убедиться, что превью показывает те же упражнения и подходы.
2. Из `/history` тапнуть «🔁 Повторить» на более старой карточке — то же самое.
3. На экране превью: заменить подходы одного упражнения через «✏️», убедиться, что заменились (не задвоились); удалить упражнение через «🗑»; добавить новое через «➕»; завершить — проверить итоговую запись в `/history`.
4. Отменить повтор («❌ Отменить») — черновик должен очиститься, ничего не сохраниться.
5. Проверить блокировку конфликта: начать `/new_workout`, не завершая — попробовать «🔁 Повторить» на карточке из истории, должно показать сообщение о незавершённой тренировке (не сломать текущий черновик).
6. Проверить, что для кардио/бассейна/смешанной тренировки кнопка «Повторить» не показывается ни после `/done`, ни в `/history`.
7. Попробовать повторить, затем удалить исходную тренировку до завершения повтора, затем попробовать повторить её ещё раз тем же (устаревшим) callback — должно показать «не найдена», не крашиться.

## Вне области этого спека

- Кардио/бассейн/смешанные тренировки — отдельное расширение позже, если понадобится.
- Именованные шаблоны (сохранить тренировку под именем и повторять её независимо от истории).
- Правка разминки на экране предпросмотра (уже доступна через обычную правку сохранённой тренировки после сохранения).
- Аналогичная функциональность в Mini App.
